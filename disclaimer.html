3. Conversion Accuracy Limitations

MarkConvert uses a CommonMark-compliant parser tested against 652 official specification tests with 98.7% accuracy. However, the following limitations may affect conversion fidelity. The output quality depends entirely on the quality and correctness of your Markdown input. Garbage in equals garbage out — malformed Markdown will produce malformed documents. Our parser follows the CommonMark specification strictly; Markdown extensions used by specific platforms (GitHub Flavored Markdown additions beyond CommonMark, Obsidian wikilinks, R Markdown code chunks, MDX components) may not be recognized or may be rendered as plain text. Complex nested structures exceeding three levels of list indentation, tables within blockquotes, or code blocks within list items may lose structural integrity during conversion. Very large documents exceeding 100,000 words may experience performance degradation or browser memory limitations depending on your device specifications.

4. Factors Not Accounted For

The following factors are outside the scope of MarkConvert's conversion capabilities and may affect the usability of your exported documents:

  • Platform-specific rendering: The same DOCX file may render differently in Microsoft Word, Google Docs, LibreOffice Writer, and Apple Pages due to differences in how each application interprets Open XML styling.
  • Font availability: If the selected export font (e.g., Calibri, Georgia) is not installed on the recipient's computer, the document viewer will substitute a fallback font, which may alter the document's appearance and pagination.
  • Image accessibility: Images referenced via URL in your Markdown require that the URL remains publicly accessible. If the image URL becomes unavailable after export, the image will not display in the document.
  • Print margins: PDF output uses the browser's print engine, and actual print margins may vary depending on your printer settings and the browser used to generate the PDF.
  • Character encoding: While we support UTF-8 encoding comprehensively, certain rare Unicode characters, complex scripts (such as right-to-left languages), or emoji sequences may not render consistently across all output formats.
  • Page breaks: Automatic page break positioning in PDF output is determined by the browser's print engine and cannot be precisely controlled. Content may break in unexpected locations, particularly within large tables or code blocks.
  • Accessibility compliance: Exported documents are not guaranteed to meet WCAG, Section 508, or other accessibility standards. If your documents must comply with accessibility regulations, additional manual formatting in the target application may be necessary.
  • Version compatibility: DOC format output is designed for compatibility with Word 97-2003 but is actually a DOCX file with a .doc extension for maximum compatibility. Very old Word versions (pre-2003) may not open these files correctly.
